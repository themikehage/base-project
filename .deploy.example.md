## 2. Standard Redeploy Flow

> Run through `/SHIP` (`.agents/routines/SHIP.md`). Production deploys need explicit human approval each time.

### Step 1: Validate Locally
```bash
<pm> run verify
```

### Step 2: Integrate
```bash
git push origin <branch>
gh pr create
```
Merge to `main` only when the user approves (or project rules allow); Coolify deploys from `main`.

### Step 3: Trigger Deploy
```bash
bun run .agents/skills/coolify/scripts/coolify-cli.ts deploy {{UUID}}
```

### Step 4: Verify Health
```bash
bun run .agents/skills/coolify/scripts/coolify-cli.ts health https://{{PROJECT}}.your-domain.com
```

### Step 5: Smoke the Change
Exercise the behavior this release delivered (HTTP call or `agent-browser`):
- {{SMOKE_CHECK_1}}

## Rollback

Trigger: health or smoke fails after deploy. Roll back first, report after.

1. Coolify → application `{{UUID}}` → Deployments → redeploy the previous successful deployment; **or**
2. `git revert <commit>` → push → deploy again.
3. Re-run Steps 4–5 to confirm recovery. Data migrations are not undone by this — restore from backup (human decision).
